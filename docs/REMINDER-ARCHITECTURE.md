# Уведомления: решение и границы

База изменений — существующий `SmirKita/design4sales-calendar`, ревизия `dca7e30`. Проект React/Vite на GitHub Pages. `src/data/telegramPlan.js` и архив тем сохранены без изменений. В исходнике было пять архивных материалов, 17 активных записей (включая рабочую запись), четыре независимых этапа, сохранение прогресса в localStorage v4, миграция v2/v3 и резервный JSON. В карточках упоминались проверки V24/V72; уведомлений ОС и интеграций не было.

| Вариант | Вывод |
| --- | --- |
| GitHub Pages | Публикует статический интерфейс. Открытая страница может хранить свой прогресс, но не обладает системным разрешением EventKit или доступом к файлам другого устройства. |
| Нативный помощник macOS | Выбран. EventKit даёт чтение и запись задач после полного доступа. Тот же интерфейс работает в WKWebView; сохранение и команда помощнику происходят в одном приложении. Аккаунт Apple и iCloud синхронизируют задачи. |
| Apple «Команды» | Персональную автоматизацию можно запускать автоматически по поддерживаемым триггерам. Для полной сверки нужны источник плана, повторяемые идентификаторы, поиск, удаление и обработка ошибок; сама автоматизация привязана к устройству. Для этого проекта связка с EventKit требует меньше ручной настройки и проще проверяется. |
| Импорт / экспорт | JSON подходит для переноса прогресса и восстановления. Снимок не обновит задачи после следующей правки. ICS относится к событиям календаря и не выбран как канал управления списком Apple «Напоминания». |
| Google Calendar | API позволяет менять события и их уведомления через OAuth. Это возможная отдельная интеграция, если понадобятся серверные сигналы или общий доступ; она создаёт события Google Calendar и не записывает задачи в Apple Reminders. В текущий выпуск не включена. |
| Общее хранилище плана | Для редактирования с iPhone и Mac одновременно нужен общий аутентифицированный источник и разрешение конфликтов: например, приватная облачная БД с бесплатным тарифом на старте или собственный сервер. Тогда Mac сможет подтягивать изменения и передавать их в Apple. В текущей версии выбран один источник на Mac: нет токенов, внешнего хранения публикаций и расходов на сервер. |

Источники: [Apple EventKit: доступ к хранилищу](https://developer.apple.com/documentation/eventkit/accessing-the-event-store), [Apple: создание задач и алармов](https://developer.apple.com/documentation/eventkit/creating-events-and-reminders), [Apple: iCloud Reminders](https://support.apple.com/guide/icloud/set-up-reminders-mmbf52194b5a/icloud), [Apple: автоматизации «Команд»](https://support.apple.com/guide/shortcuts-mac/intro-to-automation-shortcuts-apd690170742/mac), [Google: создание событий](https://developers.google.com/workspace/calendar/api/guides/create-events), [Google: уведомления Calendar API](https://developers.google.com/workspace/calendar/api/concepts/reminders).

Данные и расчёт расписания общие для обеих сборок. Схема прогресса v5 продолжает использовать существующий браузерный ключ v4, чтобы обновление страницы не потеряло данные. Отдельные выходы хранятся рядом с существующими полями карточки. Локальный Mac-файл атомарно сохраняет состояние, вычисленный набор задач и ревизию. Веб-интерфейс не передаёт план на GitHub.

EventKit сверяет один доступный для записи список **Design4Sales**. Владелец один раз выбирает список из iCloud, приложение хранит идентификаторы списка и источника. API показывает имя и тип источника, поэтому название «iCloud» служит подсказкой в диалоге. При смене идентификатора требуется новое подтверждение. Идентификатор задачи состоит из ID темы и площадки, сводки — из даты МСК, статистики — из ID темы, площадки и окна. В конце заметки стоят метка приложения, идентификатор и отпечаток значимых полей. Прежняя метка в начале заметки также распознаётся. Сверка правит только задачи с этой меткой. Неизменённые задачи не переписываются, личные записи и завершённая история не удаляются. Ошибка записи не обновляет время последней успешной сверки. Статус сети и сверка на Mac показаны отдельно от доставки iCloud.

## Сборка и проверки

```sh
npm ci
npm run check
npm run build
npm run check:mac
npm run build:mac
```

Mac-сборка требует Xcode Command Line Tools и Apple Silicon. Результат — `release/Design4Sales Calendar.app`. Веб-сборка — `dist/`; workflow GitHub Pages публикует её после проверки и слияния в `main`. Приложение не загружает код с веб-сайта; интерфейс упакован внутрь.

`npm run check` проверяет текущий набор данных, архив, миграцию, время Москвы, отмену, независимый перенос, сводки, статистику и восстановление. `npm run check:mac` проверяет план обновлений, дубли, персональные записи и локальный файл без доступа к реальному списку Apple. Для отдельного прогона WebKit:

```sh
bash macos/smoke.sh
```

Проверочная сборка открывает временный календарь и проверяет импорт v4, редактирование, сохранение при завершении процесса, повторный запуск и восстановление после повреждения файла. Доставку системных уведомлений проверяй на устройствах по [инструкции](APPLE-REMINDERS.md).
